total-recall v4.7.0-beta.1

Prerelease (npm dist-tag beta). A release version bump is now one checked command, the release archives and the provisioning manifest carry a build attestation, and a reinstall of the same version restores the engine from a per-user cache instead of downloading it again. This is the first real run of the attestation step, the version/tag check job and the archive cache.

Added
- A release version bump is one command, and a mismatch fails the release (#62): `node scripts/sync-version.js <version>` sets all seven version files, `--check` verifies them, and a `check-version` job in release.yml fails a tag that differs from the version files before anything is built.
- The release archives and provisioning.manifest.json carry a build attestation (#64): the publish job runs actions/attest@v4 before the assets are attached. Verify with `gh attestation verify <file> --repo strvmarv/total-recall`. The shim still checks only the sha256 from the manifest.
- A reinstall of the same version no longer downloads the engine again (#65): an archive verified against the release manifest is also kept in <data dir>/cache/binaries/<version>/ and restored before the manifest is fetched, so it works offline. Only manifest-verified, extracted, payload-checked archives are cached, the cache keeps one version, cache/ is owner-only, and any cache problem is a miss, never an error.

Changed
- Comments that pointed at the deleted TypeScript implementation were removed or rewritten, and a test keeps them out (#66).
