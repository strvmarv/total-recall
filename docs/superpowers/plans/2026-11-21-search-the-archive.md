# Search the archive by meaning and by words (Part 3 of the transcript archive) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** With the archive on and populated, `transcript_search` finds stored dialogue by meaning and by words (own relative ranking, three scopes, automated sessions left out unless asked), chunks get vectors from a resumable background worker triggered by `transcripts backfill`, a new `transcripts embed` and one bounded pass per `session_start`, and `transcripts status` shows the embedding progress.

**Architecture:** Archive migration 3 adds a `tx_chunk_vec` vec0 table (metadata columns, cosine) kept right by triggers on `tx_chunk` and `tx_session`; `ITranscriptStore` grows an embed write side (work queue, one-transaction `StoreEmbeddings`, lease, fingerprint, counts) and a search read side (one read transaction). A pure `EmbedGate` decides whether and how the worker may run; `TranscriptEmbedWorker` embeds in batches outside the write lock; `TranscriptSearchService` merges vector, phrase and word candidates by reciprocal rank fusion and applies the multipliers and the per-session cap; `ArchivePass` (ingest then embed, budgeted, fire-and-forget) is kicked from `SessionStartHandler`; the Server handler and the CLI commands are thin.

**Tech Stack:** C# 14 / .NET 10 NativeAOT (Infrastructure, Server, Cli), Microsoft.Data.Sqlite + FTS5 + sqlite-vec 0.1.9 (`vec0`), `System.Text.Json` source generation (`JsonContext`), xunit, the real bge-small model in tests.

**Spec:** `docs/superpowers/specs/2026-11-21-search-the-archive-design.md` (parent: `docs/superpowers/specs/2026-11-18-transcript-archive-design.md`, "Shared decisions" 7, 9, 10, 13, 14). Read the spec sections named in each task before starting it; the spec is the source of truth for every rule this plan names but does not repeat. The spec is read-only.

## Global Constraints

- Work only inside this worktree. One-line commit messages, no trailers of any kind (no `Co-Authored-By`, no AI attribution).
- NativeAOT: no reflection-based JSON (the search answer goes through source-generated `JsonContext` DTOs registered in `src/TotalRecall.Server/JsonContext.cs`); regexes are interpreted only (no `RegexOptions.Compiled`).
- Never edit `MigrationRunner`, the main migration array (stays at 18) or archive migrations 1 and 2. Add archive migration 3 only, and change `TranscriptMigrationRunner.Run` only as Task 1 says.
- Vector table: `vec0(session_id integer, project text, kind text, ts integer, embedding float[384] distance_metric=cosine)`, rowid = `tx_chunk.id`; the dimension is 384 everywhere.
- Fixed values (spec): embed batch 16 chunks; lease stale after 10 minutes, value `<machine>:<pid>:<run id>:<unix ms>`; `embed_attempts` limit 3; five consecutive lone failures end a run; probe text is one fixed non-archive string (`EmbedProbe.Text`); pass embed budget 30 s or 256 chunks, pass ingest budget 15 s, one pass per process at a time and not more often than every 10 minutes; the pass's local embedder uses 2 intra-op threads; vector candidates `k = max(40, 4 × top_k)`; RRF constant 60; multipliers compaction summary 1.25, error chunk 1.20 (error-like query only), recency `1 + 0.10 · 2^(−age_days/180)`; at most 2 chunks per session (not in session scope); words query uses at most 12 tokens of 2+ characters; `top_k` 1 to 50, default 10; response text cap 40,000 characters; `since` accepts an ISO-8601 instant or a date (00:00:00 UTC).
- Exit codes of the CLI commands: 0 ok, 1 failure or cannot run, 2 usage error.
- Every SQL statement is parameterised; storage and embedder boundary catches log through `ExceptionLogger.LogChain`; nothing writes to the MCP stdout.
- The archive's own sources never reach `Sync`/`GitSync`: no new type name in those directories (the isolation test scans for `tx_`, `Transcript`, `Archive`).
- Tests carry no `Integration` trait. Tests that mutate environment variables use `[Collection("process-environment")]` (Infrastructure.Tests), `[Collection("ConsoleCapture")]` (Cli.Tests) or `[Collection("process-environment-console")]` (Server.Tests). Tests that need the real bge model use the `BgeModelFact` attribute of Task 9 (Task 9 creates it; earlier tasks use fakes only).
- Verify commands (run at Finish): the `sh verify` blocks of `.github/develop.md` (`npm ci --ignore-scripts`, the model fetch guard, `dotnet test src/TotalRecall.sln --filter "Category!=Integration"`, `npm run test:shim`, Release build + `dump-catalog | diff -u catalog.json -`).

## Review Focus

1. A chunk re-ingested, a session's kind or project changed, or a forget committed **between the worker's read and its write**: no stale scope column, no orphan vector, a forgotten session's chunk gets no vector (Task 2 `StoreEmbeddings_*`, Task 4 `Run_*BetweenReadAndWrite_*`, Task 4 `Run_KindFlippedBetweenReadAndWrite_*`, Task 11 `KindFlip_OnResume_*`).
2. A query made of FTS5 syntax or odd text (`-`, `*`, `:`, `NEAR`, `OR`, an unbalanced `"`, only punctuation, non-ASCII, 10,000 characters): never an SQL error, no tokens means no word candidates (Task 5 `Words_*`, Task 6 `Search_OddQueries_NeverThrow`).
3. Empty or tiny archives and edge arguments: no archive file, an archive with no chunks, an unknown session, a project matching nothing, an unparsable `since`, `top_k` 1 and 50, `scope=session` without a session (Task 6 `Search_*`, including `Search_UnknownSession_EmptyWithNote` and `Search_ProjectMatchingNothing_Empty`).
4. Two processes at once and a dead holder: a CLI `embed` beside a server pass, a crashed holder, a worker that slept past the lease (Task 2 `Lease_*`, Task 4 `Run_LostLease_*`, Task 11 `TwoWorkers_*`).
5. Embedder failure modes: model missing, a remote 4xx or 5xx or timeout, a wrong-sized vector, a failing probe, a chunk that always fails at the front of the queue (Task 3 gate table, Task 4 `Run_*Failure*`, Task 11 `Remote*`).
