# Git sync 1a-1: the git client, the lock and the tree reader Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the plumbing git sync runs on: a closed set of typed `git` commands with isolation, a hard kill, classified and redacted failures; the OS file lock; the sync-directory paths; the `ls-tree`/`diff-tree` readers and the per-entry verdicts; and the secret scanner's detector selection. Nothing calls any of it yet.

**Architecture:** Pure rules live in two new F# files in `TotalRecall.Core` (`SyncGit.fs`: commands, address and branch checks, argument lists, overrides, the environment rule, ssh composition, failure classification, redaction, keys; `SyncTree.fs`: the parsers and verdicts). `TotalRecall.Infrastructure/GitSync/` gets `GitProcess.cs` (the only place a process starts), `GitClient.cs` (one typed method per command), `GitSyncPaths.cs` and `SyncLock.cs`. `SensitiveContentScanner` gets detector selection. Tests that need `git` run in the standard verify and skip themselves when `git` is missing.

**Tech Stack:** F# (Expecto + FsCheck 2.16.6) for the pure part; C# net10 NativeAOT (xUnit 2.9.2, `System.Diagnostics.Process`, `FileStream`) for the rest. No new package.

**Spec:** `docs/superpowers/specs/2026-11-15-git-sync-git-client-design.md` (read it first; the plan gives the files, the signatures and the test lists, the spec gives the rules and the numbered decisions, cited here as "decision N"). The umbrella is `docs/superpowers/specs/2026-11-15-git-sync-design.md`. Issue #120.

## Global Constraints

- The spec file is read-only for the whole run. Commits carry no trailer and no AI attribution; messages are plain imperative sentences. No CHANGELOG change (nothing user-visible).
- Core has no I/O and no mutable state, and uses no `%A` or reflection serialization; C# is AOT-safe (no reflection serializer, no `Regex` with `RegexOptions.Compiled`). No new package.
- No `git` invocation exists outside `GitCommand`: no free-form argument list reaches a process. No case of `GitCommand` produces `--force`, `-f`, `--force-with-lease`, `--delete`, `--mirror`, `--prune`, a `+` outside the fetch refspec, or a push refspec other than `HEAD:refs/heads/<branch>` (decisions 1, 8).
- A message, result or exception never carries credentials from a remote address (decision 12).
- Windows is the owner's platform: helpers take the executable path and the case-insensitivity as arguments, and paths are built with `Path.Combine`; nothing assumes `/`.
- New F# files are added after `Config.fs` in `TotalRecall.Core.fsproj` (they use `GitSyncSettings` and `SyncValidation`), and their test files after `GitSyncConfigTests.fs` in `TotalRecall.Core.Tests.fsproj`. New C# files go in `src/TotalRecall.Infrastructure/GitSync/` (namespace `TotalRecall.Infrastructure.GitSync`) and their tests in `tests/TotalRecall.Infrastructure.Tests/GitSync/` (namespace `TotalRecall.Infrastructure.Tests.GitSync`), **without** the `Integration` trait.
- Test commands: `dotnet test tests/TotalRecall.Core.Tests/TotalRecall.Core.Tests.fsproj`; `dotnet test tests/TotalRecall.Infrastructure.Tests/TotalRecall.Infrastructure.Tests.csproj --filter "FullyQualifiedName~GitSync"`. The worktree already ran `npm ci --ignore-scripts` and `sh scripts/fetch-bge-small.sh`.
- A test name quotes the spec's rule or the ticket's wording so a reviewer compares one to one. A test that needs `git` is a `[GitFact]` (Task 5) and a test that needs `sh` or `flock` skips with a reason when it is missing.

## Interpretations (recorded here because the spec is read-only)

1. **Command shapes.** `GitCommand` (module `TotalRecall.Core.SyncGit`) is: `Version | ConfigGetSshCommand of ConfigScope | Init of branch: string * dir: string | Clone of url: string * branch: string * dir: string | LsRemote of RemoteRef * branch: string | AddOrigin of url: string | SetOriginUrl of url: string | Fetch of branch: string | ResetHard of Revision | Clean | IsAncestor of Revision * Revision | RevParse of Revision | UpdateLastSynced of sha: string | DiffTree of fromRev: Revision * toRev: Revision | LsTree of Revision | LsTreeRoot of Revision | CatBlob of sha: string | Stage of StageScope | HasStaged | Commit of message: string | Push of branch: string`, with `ConfigScope = Global | System`, `RemoteRef = Url of string | Origin`, `StageScope = Memories | Manifest | Attributes`, `Revision = Head | Sha of string | RemoteBranch of string | LocalBranch of string | LastSynced`. The spec's `UpdateRef(name, sha)` is `UpdateLastSynced sha` (the only name it allows), and `Init`/`Clone` carry the target directory the spec's table writes as `<clone>`.
2. **Argument building.** `SyncGit.build (ctx: BuildContext) (cmd: GitCommand) : Result<string list, string>` validates and returns the **whole** argument list (the leading `--git-dir=<clone>/.git --work-tree=<clone>` for a clone-scoped command, then the `-c` overrides unless the command takes none, then the subcommand). `BuildContext = { CloneDir: string; NoHooksDir: string; EmptyFile: string; Windows: bool }`. `commandArgs` (the part after the overrides) is also public, for the table-driven tests.
3. **Failure input.** `FailureInput = { ExitCode: int option; TimedOut: bool; Cancelled: bool; SpawnFailed: bool; OutputTooLarge: bool; Stderr: string }`; `classifyFailure : FailureInput -> FailureKind` with `FailureKind = NoGit | GitTooOld | TimedOut | Cancelled | Auth | RemoteNotFound | Network | NonFastForward | RemoteBranchMissing | NotARepository | OutputTooLarge | Other`. `GitTooOld` is not produced by `classifyFailure`: `SyncGit.parseVersion`/`isSupportedVersion` decide it and `GitClient.VersionAsync` returns it.
4. **Redaction.** `SyncGit.redact (secrets: string list) (text: string)` replaces the user-info of every `scheme://user[:pass]@` with `***@` and every literal in `secrets` with `***`; `SyncGit.cleanStderr (secrets) (raw)` splits on `\n`, keeps for each line only the text after its last `\r`, redacts each line, joins them and keeps the last 2048 UTF-16 code units. The C# runner applies `redact` to every segment as it is read (before any capture limit) and `cleanStderr` shape to the retained tail.
5. **Process seam.** `IGitProcess.RunAsync(GitCommand, GitContext, GitRunOptions, CancellationToken)` (the spec's `RunAsync(command, options, cancellation)` with the paths folded into a `GitContext`); `GitContext = (string Executable, string CloneDirectory, string NoHooksDirectory, string EmptyFile)`. `GitExecutable.TryFind` (PATH search, `git.exe` on Windows) is a small helper in `GitProcess.cs` for the tests and the later `OpenGit`.
6. **Result type.** `GitOutcome<T>` is a readonly record struct with `IsOk`, `Value` (valid when ok) and `Failure` (the `GitResult`, valid when not ok), plus `static Ok(T)` / `Fail(GitResult)`. `GitResult` is `(int? ExitCode, byte[] Stdout, string StderrText, FailureKind? Failure, TimeSpan Elapsed)`; `Failure` is null exactly when the exit code is 0.
7. **`Stage`** treats exit 128 as success only when the redacted standard error contains `did not match any files` (decision 16); the client reads the raw text for that test before it is trimmed.
8. **`GitFact`.** An `internal sealed class GitFactAttribute : FactAttribute` (as `PgFactAttribute` does) sets `Skip` when `GitExecutable.TryFind()` returns nothing or the version is below 2.28.
9. **Windows case-insensitivity** is passed as a boolean (`GitSyncPaths.For(dbPath, remote, caseInsensitive)`); production callers pass `OperatingSystem.IsWindows() || OperatingSystem.IsMacOS()`.
10. **Test isolation of git configuration.** Every real-git test builds a throwaway home directory and passes `HOME`, `XDG_CONFIG_HOME` and `USERPROFILE` through `EnvironmentOverrides` (and writes its `.gitconfig` there), so it never reads or writes the developer's configuration.

## Review Focus

1. A remote whose user-info carries a token appears in no result, exception or callback segment, even when a size limit cuts the URL [Tasks 2, 4].
2. A damaged clone (no `.git`) inside another git repository: `reset --hard` and `clean` fail and the other repository is untouched [Task 5].
3. A repository holding a symlink, a submodule entry, a path-like id, a wrong shard, a nested path or an oversized file [Tasks 3, 6].
4. A user's global git configuration with signing, hooks, an askpass program, an attributes filter and a `core.sshCommand` [Task 5].
5. A remote that accepts the connection and never answers, and a call that is cancelled [Task 4, 5].
6. Two database files in one directory sharing a clone or a lock [Task 5, 7].
