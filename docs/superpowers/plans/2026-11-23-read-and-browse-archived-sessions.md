# Read and browse archived sessions (Part 4 of the transcript archive) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** With the archive on, `transcript_get` returns the exchanges around a search hit (or a stated range of one session) as readable text within a token budget the caller can raise, saying when it left something out and how to read on; `transcript_sessions` lists archived sessions newest first with titles, hiding automated ones unless asked. Both keep Part 1's off answer.

**Architecture:** `ITranscriptStore.BeginReads()` returns an `ITranscriptReads` (one deferred read transaction, no writes) with exact queries for exchanges and sessions. A pure `ExchangeText` joins an exchange's parts. `TranscriptReadService` (Infrastructure) turns a request into a response: it opens the archive per call with `create: false`, reads inside one `BeginReads()`, applies the budget algorithm and the paging pointers, and returns records or an error string. `TranscriptGetHandler` and `TranscriptSessionsHandler` (Server) parse arguments with two new strict readers, call the service and serialise source-generated DTOs. No schema change, no CLI change.

**Tech Stack:** C# 14 / .NET 10 NativeAOT (Infrastructure, Server), Microsoft.Data.Sqlite, `System.Text.Json` source generation (`JsonContext`), xunit. No embedder and no model are used.

**Spec:** `docs/superpowers/specs/2026-11-23-read-and-browse-archived-sessions-design.md` (parent: `docs/superpowers/specs/2026-11-18-transcript-archive-design.md`, decisions 3, 9, 10; Part 3 spec `docs/superpowers/specs/2026-11-21-search-the-archive-design.md` for the read-transaction pattern). Read the spec sections named in each task before starting it; the spec is the source of truth for every rule this plan names but does not repeat (the answer shapes, the exact error strings, the budget order and the paging pointers are in its sections 2 and 3).

- Fixed values (spec): `context` 0 to 10 (default 1); `max_tokens` 200 to 20,000 (default 2,000); a range at most 200 exchanges wide; `limit` 1 to 100 (default 20); a budget counts the sum of `ceil(chars / 4)` per returned exchange; cut marker text `[cut: raise max_tokens to read the rest]`; error strings of the spec section 2 verbatim.

Tests that change environment variables use `[Collection("process-environment")]` (Infrastructure.Tests), `[Collection("ConsoleCapture")]` (Cli.Tests) or `[Collection("process-environment-console")]` (Server.Tests). Run one `dotnet test <project> --filter ...` per project (a combined command fails with MSB1008).

## Review Focus

1. A forget, an ingest commit or a reset row **between two calls or inside one read**: no mixed session, an unknown session reported as unknown even when it was the only one archived (Task 2 `Reads_AreOneTransaction_*`, Task 4 `Get_*Forgotten*`, Task 7 `Forget_BetweenCalls_*`).
2. A requested range with a **huge exchange in the middle**, a window where **every** exchange is over budget, `max_tokens` 200 with a 5,000-character exchange, a range whose first stored exchange is not `from` (gaps), a range entirely past the session's end: no loop when reading on, no exchange twice, `approxTokens` never above `max_tokens` (Task 4 `Get_Paging_*`, `Get_FirstExchangeOverBudget_*`, `Get_Gaps_*`, `Get_RangePastEnd_*`).
3. Odd arguments: `id` 0 or negative, a session name with a second colon (`claude-code:a:b`), `from_exchange` above `to_exchange`, `context: 1.5`, `2.0`, a string where a number belongs, a missing `arguments`, `arguments` as an array (Task 1, Task 6 `*_Arguments_*`).
4. An exchange text that looks like the plumbing: a compaction summary that starts with `User: ` and a later part that starts with `User (continued): `, an exchange with no user text, an empty-bodied chunk (Task 3 `Join_*` including `Join_HeaderOnlyChunk_*`, Task 4 `Get_CompactionSummary_*`).
5. Sessions that are not what the list expects: no `started_at` or `ended_at`, a reset row with no chunks, two sessions with identical last activity, `before` equal to a session's own end time, a project that matches nothing in a non-empty archive (Task 2 `ListSessions_*`, Task 5 `Sessions_*`).
