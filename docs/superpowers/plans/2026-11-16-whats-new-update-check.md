# What's-new notice: update check Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A user running an older release is told once per host and release that a newer one is available, with a one-line summary, the update instruction for their host and the release's link; the engine learns about releases from a background GitHub request at most once a day, which a setting or an environment variable switches off and the privacy policy discloses (issue #115, ticket T3 of the what's-new notice, tracking issue #92).

**Architecture:** A background `UpdateChecker` (Infrastructure, started only from `Program.RunServeAsync`) writes `<dataDir>/whats-new/latest-<channel>.json`. The pure `WhatsNewDecider` gains the Available rule (after first seen and updated), `WhatsNewState` keeps a per-channel `availableSeen` mark beside `version`, and `WhatsNewRenderer` composes the `<how>` from a per-host table (`UpdateInstructions`). `WhatsNewService` (relayed line) and `WhatsNewCommand` (direct channels) read the latest file and the switches; the service also remembers, in memory, every host it marked so one engine gives one notice per host.

**Tech Stack:** .NET 10 / C# (xUnit, NativeAOT, no reflection JSON, `JsonDocument` + `TotalRecall.Infrastructure.Json.JsonWriter`, `HttpClient`), plain ESM JavaScript (`node:test`, zero dependencies), Markdown.

**Spec:** `docs/superpowers/specs/2026-11-15-whats-new-notice-design.md` (READ-ONLY). T3 content: section 2 (rules Available and One notice per start, the Update checker bullets, the config table, the env var paragraph, "Build decisions for the update checker (T3)"), section 3 (T3 extensions), section 4 "Rendering", section 5, "Decided by the owner", "Accepted losses". Ticket: `.superpowers/ticket-115-body.md` (20 acceptance criteria; mapped at the end of this plan).

## Global Constraints

- Commits: one-line imperative message, no trailers, no `Co-Authored-By`, no AI attribution anywhere.
- Shell is bash. JS tests run by explicit file paths (`node --test a.test.js b.test.js`; Node 24 rejects a directory) or `npm run test:shim`. A new JS test file is added to `SHIM_TEST_TARGETS` in `scripts/run-shim-tests.js` unless it lives under a directory already listed there (`bin/shim/`, `pi/`, `codex/`, `copilot/`, `cursor/`, `skills/develop/`).
- Tests never set `TOTAL_RECALL_HOME`, `HOME` or `TOTAL_RECALL_NO_UPDATE_CHECK` on the test process, never call `Environment.SetEnvironmentVariable`, never read or write the real `~/.total-recall`, and never make a real network request: every C# test that needs a directory uses `Path.Combine(Path.GetTempPath(), "tr-<name>-" + Guid.NewGuid().ToString("N"))` and deletes it; every `UpdateChecker` in a test gets a fake `HttpMessageHandler`, a fake clock and a fake delay; every `ConfigLoader` read in a test passes an explicit user config path inside a temp dir.
- AOT: no reflection serialization. Parse with `JsonDocument`, write with `JsonWriter.AppendString` into a `StringBuilder`. Do not modify existing migrations. No new package dependency.
- Existing public signatures stay source-compatible: new parameters are optional trailing ones (`WhatsNewDecider.Decide`, `Notice`, `WhatsNewRenderer.Line`, `WhatsNewService`, `WhatsNewCommand`).
- Host ids (closed list, `HostIds.Known`): `claude-code, pi, copilot-cli, cursor, codex, gemini-cli, kiro, opencode, hermes, cline, windsurf, zed, vscode, other`. Channels: `stable` (running version has no prerelease part after build metadata is stripped) and `pre`.
- State directory `<dataDir>/whats-new/` (`WhatsNewState.DefaultDir()`). Files: `seen-<host>.json` = `{"version":"4.8.0","availableSeen":{"stable":"4.9.0","pre":"4.10.0-beta.1"}}` (each key omitted when it has no value; `availableSeen` keys in the order `stable`, `pre`); `latest-stable.json` / `latest-pre.json` = `{"version":"4.9.0","summary":"...","checkedAt":"2026-11-16T10:00:00.000Z","lastAttempt":"2026-11-16T10:00:00.000Z"}` (keys in that order, each omitted when it has no value; times ISO 8601 UTC, format `yyyy-MM-dd'T'HH:mm:ss.fff'Z'`, as JavaScript's `toISOString`). All writes atomic (temp file `<path>.<guid N>.tmp` + `File.Move(overwrite: true)`, temp deleted in `finally`, every IO error swallowed); all reads fail-safe (any error is "no state").
- A release version taken from GitHub or from a latest file is valid only when it is at most 64 characters, contains no `+`, and `SemVer.TryParse` accepts it (which also rejects a leading `v`).
- Notice lines (exact shapes, single spaces): first seen `total-recall <v>: <summary> All releases: <releasesUrl>`; updated as today; available `total-recall <newer> is available (you have <running>): <summary> Update: <how> More: https://github.com/strvmarv/total-recall/releases/tag/v<newer>`; an empty summary drops itself and its leading space (`...(you have 4.8.0): Update: ...`). Every line is at most 1000 characters.
- `<how>` table (single source, `UpdateInstructions`): `claude-code` `/total-recall:commands update`; `pi` `pi update`; `copilot-cli` `copilot plugin update total-recall@strvmarv-total-recall-marketplace`; `gemini-cli`, `kiro`, `opencode`, `hermes`, `cline`, `windsurf`, `zed`, `vscode` `npm install -g @strvmarv/total-recall`; `cursor` `see docs/hosts/cursor.md`; `codex` `see docs/hosts/codex-cli.md`; `other` `see docs/hosts/other-mcp.md`. Nothing from the network ever becomes part of `<how>` or the link.
- `TOTAL_RECALL_NO_UPDATE_CHECK`: disables the check for any value that is non-empty after `Trim()` and is neither `0` nor `false` (ordinal, case-insensitive); null, empty, whitespace-only, `0`, `false` leave `updates.check` to decide. The check is on only when `updates.notice` AND `updates.check` are true AND the variable does not disable it. `updates.check_interval_hours`: a TOML integer from 1 to 8760, anything else 24.
- Checker constants: base address `https://api.github.com/`; stable path `repos/strvmarv/total-recall/releases/latest`; prerelease path `repos/strvmarv/total-recall/releases?per_page=10`; headers exactly `User-Agent: total-recall/<bare running version>` and `Accept: application/vnd.github+json`; first delay 60 s; one 3 s deadline over send and read; response cap 1 MB (1,048,576 bytes); failure retry 1 h; sleep step at most 24 h; a stored time more than 1 day in the future counts as missing; redirects off.
- `WhatsNewCommand` may read exactly one environment variable, `TOTAL_RECALL_NO_UPDATE_CHECK` (production constructor only, through `UpdateSettings.NoUpdateCheckEnvVar`); it still never reads `TOTAL_RECALL_HOST` (`--host` stays the only host source).
- Final verification (Task 10) runs the `sh verify` blocks of `.github/develop.md`: `dotnet test src/TotalRecall.sln --filter "Category!=Integration"`, `npm run test:shim`, and the Release build + `dump-catalog | diff -u catalog.json -` (this ticket adds no MCP tool, so `catalog.json` is unchanged).

## Review Focus

- An unwritable or vanished state directory (read-only disk, the data dir is a file): the checker must not hot-loop re-requesting because the file never records the attempt. Pinned by `Loop_UnwritableStateDir_DoesNotHotLoop` (Task 5): it keeps the last attempt and answer times in memory and uses the later of memory and file.
- A clock that jumps (a file written on a machine whose clock was ahead, or edited by hand): a time more than a day ahead must not stop checks, and no single sleep may exceed 24 h. Pinned by `NextDue_*`, `Loop_FutureCheckedAt_DoesNotStopChecks`, `Loop_SleepsAtMost24HoursPerStep` (Task 5).
- A hand-edited or hostile `latest-<channel>.json` (huge file, `+build` or 65-character version, control characters or a markdown link in the summary): nothing it holds may lengthen the line, inject text or change the link. Pinned by `LatestReleaseStateTests.Read_*` (Task 2) and `Decide_Available_LinkIsReleasePage_SummarySanitised` (Task 3).
- A stable and a beta engine sharing one data directory and host key: neither may overwrite the other's `availableSeen`, and a stable host must never be nudged toward a prerelease. Pinned by `WriteAvailableSeen_PerChannel_DoesNotOverwriteOtherChannel` (Task 2), `Decide_StableRunning_PrereleaseLatest_IsNull` (Task 3) and `Check_StableAndBetaEnginesShareHost_AvailableSeenPerChannel` (Task 4).
- A running version carrying build metadata (`4.8.0+abc`): it is stable, the user agent and the `(you have ...)` part use the bare version. Pinned by `Request_UserAgent_UsesBareVersion` (Task 5) and `Decide_Available_RunningWithBuildMetadata_FromIsBare` (Task 3).
