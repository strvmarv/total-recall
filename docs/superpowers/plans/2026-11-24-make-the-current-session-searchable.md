# Make the current Claude Code session searchable while it runs (Part 5 of the transcript archive) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** With the archive on, text added to a running Claude Code session is found by `transcript_search` at once: a small hook writes a per-process marker, the engine finds its own marker through its ancestor pids, brings the current session's new tail into the archive before `transcript_search`, `transcript_get` and `transcript_sessions` run, and `transcript_search` defaults to the current project and session.

**Architecture:** A shell wrapper (`hooks/live-marker/run.sh`, sentinel test with builtins only) starts a pure-node writer that writes `<dataDir>/live/claude-code-<pid>.json` atomically on `SessionStart` and `UserPromptSubmit`. `LiveSessionFinder` walks `ProcessAncestry` nearest first and accepts only a marker that passes the path and process checks. `TranscriptSyncService` ingests the current session through `TranscriptIngester` (2 s budget) and, for search only, embeds up to 8 chunks with the session preferred (a new optional argument on the embed queue and worker). `TranscriptSearchService.Plan` defaults scope from the marker. No schema change, no CLI change, no new tool.

**Tech Stack:** C# 14 / .NET 10 NativeAOT (Infrastructure, Server), Microsoft.Data.Sqlite, source-generated JSON (`JsonContext`), xunit; zero-dependency Node ESM and bash for the hook (`node --test`, run by `npm run test:shim`).

**Spec:** `docs/superpowers/specs/2026-11-24-make-the-current-session-searchable-design.md` (parent: `docs/superpowers/specs/2026-11-18-transcript-archive-design.md`, decisions 7, 9, 10, 12; Part 3 spec `2026-11-21-search-the-archive-design.md`; Part 4 spec `2026-11-23-read-and-browse-archived-sessions-design.md`). Section numbers below are the sub-spec's unless said otherwise.

## Global Constraints

- Work only inside this worktree. One-line commit messages, no trailers of any kind (no `Co-Authored-By`, no AI attribution). Implementers never push.
- The spec is read-only (never edit `docs/superpowers/specs/`).
- NativeAOT: no reflection-based JSON (answers go through source-generated DTOs registered in `src/TotalRecall.Server/JsonContext.cs`); regexes interpreted only (no `RegexOptions.Compiled`). The component checks of section 2 use `FileSystemInfo.LinkTarget`, no P/Invoke is required.
- No schema change: never touch `TranscriptSchema.cs` or the main migration array (18). No change in `TotalRecall.Cli`. No new MCP tool, no new setting.
- Fixed values (spec): marker file `<dataDir>/live/claude-code-<pid>.json`, fields `v` (1), `host` (`claude-code`), `host_pid`, `session_id`, `transcript_path`, `cwd`, `at` (UTC, milliseconds, `Z`); marker read cap 16 KiB; hook payload cap 64 KiB and 500 ms of stdin; writer deadline 3 s; hook `timeout` 5; prune only on `SessionStart`, at most 200 names looked at, pid dead (`ESRCH`; `EPERM` is alive) or file older than 30 days, `*.tmp` older than 1 hour; ancestor chain at most 12 hops, `ps` 1 s per hop and 3 s in total; guess window 30 minutes; sync ingest budget 2 s, embed budget `EmbedBudget(2 s, 8 chunks)`, no further step after 6 s in total, busy timeout about 500 ms per lock wait; session id rule is `ClaudeCodeAdapter.IsValidId` (1 to 128 of `A-Za-z0-9._-`); `transcript_path` at most 4096 characters.
- Every SQL statement is parameterised; storage-boundary catches log through `ExceptionLogger.LogChain` (stderr, never stdout); the hook prints nothing to stdout or stderr on any path.
- Nothing here may reach `Sync`/`GitSync` (the isolation tests scan those directories for `tx_`, `Transcript`, `Archive`; markers are local files under `<dataDir>/live/` and are never synced).
- Tests carry no `Integration` trait. Tests that change environment variables use `[Collection("process-environment")]` (Infrastructure.Tests), `[Collection("ConsoleCapture")]` (Cli.Tests) or `[Collection("process-environment-console")]` (Server.Tests, when they also capture the console). `Server.Tests` and `Cli.Tests` compile `tests/TotalRecall.Infrastructure.Tests/Transcripts/Support/*.cs` by `Compile Include`: files there use the **public** API only.
- Verify commands (run at Finish): the `sh verify` blocks of `.github/develop.md`.

## Review Focus

1. **A marker for the wrong process or a stale one**: two sessions in one directory, a pid reused by a newer process (marker older than the process start), a nested host (inner marker refused, outer valid), the walk continuing past a refused marker (Task 3 `Find_*`, Task 2 simulated hosts).
2. **A hook that must never hurt a prompt**: garbage or oversized stdin, stdin that never closes, a `cwd` with a newline or unicode, a relative or NUL-holding `transcript_path`, `session_id` `..` or 129 characters, an unwritable `live/`, `node` missing from `PATH` (Task 1 table, Task 2 `Run_*`).
3. **The tail of a growing file**: a session file that grows during the sync, is deleted between the stat and the read, or whose first ingest exceeds the budget; two syncs at once (Task 5 `Sync_*`).
4. **The embed step under pressure**: a 20,000-chunk backlog older than the session, current-session chunk ids lower than the backlog's, a gate that refuses (remote provider without opt-in, model not ready), a held lease, a busy archive (Task 4 `NextEmbedWork_*`, Task 5 `SyncEmbed_*`, Task 7).
5. **Defaults from a marker that disagrees with the archive**: a marker `cwd` different from the session file's first `cwd`, an automated current session, a session forgotten or unarchived, `scope: "session"` with no marker, an unknown scope (Task 6 `Plan_*`, `Handler_*`).
